\section{Arquitectura}

A continuación se presenta la arquitectura de TREEBAR, la aplicación
móvil objetivo del proyecto. Se mostrará lo siguiente: tipo de arquitectura, patrones
arquitectónicos, tecnologías  seleccionadas, así como los criterios que guiaron 
cada decisión de diseño.

\subsection{Sistema}

El sistema adoptará una \textbf{arquitectura cliente-servidor} con un backend
monolítico modular, implementando el patrón de diseño \textit{gateway
aggregation} con el objetivo de centralizar la lógica de integración con
múltiples fuentes externas.

El patrón gateway aggregation —mostrado en la
Figura~\ref{fig:gateway-aggregation}— consiste en utilizar un componente
intermediario que recibe una sola petición del cliente, la descompone en
múltiples llamadas a servicios backend, agrega los resultados y devuelve una
única respuesta.

\begin{figure}[ht]
    \centering
    \fbox{\includegraphics[width=0.8\textwidth]{imagenes/gateway-aggregation.png}}
    \caption{Gateway Aggregation}\label{fig:gateway-aggregation}
\end{figure}

Al utilizar este patrón, se pretende que el sistema tenga la capacidad de hacer llamadas
a diversas APIs externas, devolviendo al cliente una sola respuesta basada en
la información obtenida por cada API.\@

Esto resulta especialmente útil para TREEBAR por tres
razones principales. 
\begin{enumerate}
    \item Los usuarios interactúan con la aplicación desde dispositivos móviles, donde
          la latencia de red es variable e inpredecible; realizar cuatro llamadas secuenciales
          desde el cliente puede multiplicar dicha latencia, mientras que el gateway las ejecuta
          en paralelo desde una conexión estable en el servidor.
    
    \item Las credenciales de acceso a las APIs permanecen confinadas al sistema, eliminando el
          riesgo de esposición al cliente.

    \item Si en un futuro se incorpora una nueva fuente de datos, el cambio se realiza unicamente
          en el gateway sin modificar la aplicación móvil.
\end{enumerate}
